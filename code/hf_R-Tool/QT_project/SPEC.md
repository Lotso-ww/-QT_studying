# RFID 标签业务功能规格说明

## 1. 文档目的

本文档定义当前 Qt 高频 RFID 工具需要实现的业务功能、数据协议、模块边界、错误处理、日志格式和验收标准。

实现基于现有工程，不重写底层读写器驱动。现有工程中的 `CAEDevice_HF` 负责设备和标签底层通信；新增业务代码必须通过独立服务和协议编解码模块组织，避免继续把业务逻辑堆积到 `MainWindow`。

## 2. 范围

### 2.1 本期范围

- RFID 读写器初始化与关闭
- 高频标签持续盘点
- 标签 UID 稳定性判断
- 标签业务数据读取
- 标签业务数据写入
- 读写异常捕获和最多三次重试
- 过程日志输出
- 标签数据的 HEX 展示和字段解析
- 基于 ISO15693 block 的分块读写

### 2.2 非本期范围

- 新增 RFID 芯片协议或更换读写器厂商驱动
- 数据库、网络同步和用户权限系统
- 多标签同时业务写入
- 修改现有通用 EAS、AFI 等调试功能的协议行为

## 3. 已知硬件和软件前提

- 当前项目使用 Qt/C++ 和现有 `rfidlib` SDK。
- 当前业务目标按 ISO15693 标签实现。
- 标签业务数据从 `basic index = 0` 开始写入。
- block 大小不能写死。业务读写前必须通过标签系统信息获取 block 大小和总容量；探测失败时终止业务操作，不使用猜测值继续读写。
- 读写操作必须在读写器句柄有效、标签句柄有效、访问天线设置成功后执行。

## 4. 总体架构

```text
MainWindow
    |
    v
RfidTagService       业务流程、稳定盘点、重试、校验、结果状态
    |
    +--> TagPayloadCodec   业务数据编码、解码、校验、HEX
    |
    v
CAEDevice_HF         设备打开、盘点、标签连接、block 读写
    |
    v
rfidlib / ISO15693 SDK
```

### 4.1 `CAEDevice_HF`：设备适配层

负责：

- 读写器连接、关闭和底层错误码返回
- 天线选择
- ISO15693 盘点
- 标签连接和断开
- 读取系统信息
- 按 block 读取和写入
- 必要的通信超时复位

不负责：

- 病历号、姓名、授精时间等业务字段
- 三次重试策略
- 业务日志文案
- UI 控件操作

建议补充清晰的同步接口，供业务服务调用，例如：

```cpp
struct ReaderInitResult;
struct InventoryResult;
struct TagSystemInfo;

ReaderInitResult open(const ReaderConfig &config);
void close();
InventoryResult inventoryOnce(const AntennaList &antennas);
TagSystemInfo getSystemInfo(const TagIdentity &tag);
QByteArray readBlocks(const TagIdentity &tag, int basicIndex, int blockCount);
void writeBlocks(const TagIdentity &tag, int basicIndex, const QByteArray &data);
```

实际命名可以适配现有代码，但业务层不得直接依赖 `rfidlib` 的大量全局函数。

### 4.2 `TagPayloadCodec`：协议数据层

负责：

- 业务对象与标签字节流互转
- BCD 时间编码和解码
- GBK 姓名编码和解码
- ASCII 病历号编码和解码
- 长度字段计算
- 字段长度和字符合法性校验
- HEX 字符串生成

该模块应尽量不依赖 Qt UI 和真实 RFID 设备，可以独立测试。

### 4.3 `RfidTagService`：业务流程层

负责：

- 执行“盘点至稳定”的流程
- 选择或确认业务标签
- 标签连接和访问天线设置
- 业务 payload 的读写
- 读后校验
- 最多三次重试
- 统一生成业务结果和日志事件

### 4.4 `MainWindow`：界面层

负责：

- 输入皿序号、授精时间、女方姓名、病历号
- 发起初始化、盘点、读取、写入、停止操作
- 显示状态、进度、重试次数和日志
- 展示原始 HEX 和解析后的字段

禁止在 `MainWindow` 中直接拼接 payload、处理 GBK、计算 block 数或实现重试循环。

## 5. 业务数据模型

建议定义如下业务对象：

```cpp
struct TagPayload {
    quint8 formatVersion = 1;
    quint8 dishNumber = 0;
    QDateTime inseminationTime;
    QString femaleName;
    QByteArray medicalRecordNumber; // ASCII 原始字节
};
```

注意：病历号在业务输入层可以使用 `QString`，进入协议层后必须限制为 ASCII，并以字节长度参与长度计算。

## 6. 标签数据协议

### 6.1 字节布局

业务数据从 block 0 的第 0 字节开始连续写入：

| 偏移 | 字段 | 长度 | 编码 | 说明 |
|---:|---|---:|---|---|
| 0 | 标签格式版本号 | 1 | Byte | 当前版本固定为 `0x01` |
| 1 | 内容长度 | 1 | Byte | 固定表示偏移 2 之后的内容字节数，不包含版本号和长度字段本身 |
| 2 | 皿序号 | 1 | Byte | 例如皿号 1 为 `0x01` |
| 3 | 授精时间 | 5 | BCD 8421 | `yyMMddHHmm`，每两位十进制数字编码为一个 BCD 字节 |
| 8 | 女方姓名 | 8 | GBK | 固定 8 字节，不足前面补 `0x20` |
| 16 | 病历号 | N | ASCII | 动态长度，N 等于病历号 ASCII 字节数 |

因此：

```text
contentLength = 1 + 5 + 8 + medicalRecordNumberBytes
totalPayloadLength = 2 + contentLength
```

例如病历号为 `2678453101`，长度为 10 字节，则：

```text
contentLength = 24 = 0x18
totalPayloadLength = 26 = 0x1A
```

### 6.2 时间编码

输入时间格式：`yyMMddHHmm`，共 10 位十进制数字。

示例：

```text
2301311743 -> 0x23 0x01 0x31 0x17 0x43
```

要求：

- 年只保存两位；
- 月范围 01-12；
- 日、时、分必须通过日期时间对象校验；
- 不允许直接把 ASCII 字符写入标签；
- 两位年份固定解释为 2000-2099，即 `00` 表示 2000 年、`99` 表示 2099 年。

### 6.3 女方姓名编码

- 使用 GBK 编码，不使用 UTF-8；
- 编码后必须正好占 8 字节；
- 最多容纳 4 个常见双字节汉字，或 8 个单字节字符；
- 编码后不足 8 字节时，在前面填充 ASCII 空格 `0x20`；
- 编码后超过 8 字节时，拒绝写入，不允许静默截断；
- 读取后先去除前导填充空格，再转换为界面显示字符串；
- GBK 编码失败时，返回输入校验错误，不进入设备重试。

### 6.4 病历号编码

- 使用 ASCII 编码；
- 长度为动态值 N；
- 不允许为空；
- 只允许字符 `A-Z`、`a-z`、`0-9`、下划线 `_` 和连字符 `-`；
- 长度固定限制为 1-64 字节；
- 不允许空格、空字节、控制字符和其他标点符号；
- 病历号长度必须参与 `contentLength` 计算；
- 读取时以 `contentLength` 推导剩余病历号长度，不使用固定长度读取。

### 6.5 长度和容量检查

编码完成后必须检查：

1. `contentLength <= 255`，因为长度字段为 1 字节；
2. `totalPayloadLength` 不超过标签可用容量，容量不足时立即终止并返回 `CapacityExceeded`，不得截断数据或自动改写其他标签；
3. block 数量按实际 block 大小向上取整；
4. 最后一个 block 不足部分使用 `0x00` 填充，填充字节不计入 payload 长度；
5. 读取后只解析 `totalPayloadLength` 范围内的字节。

## 7. 设备初始化流程

```text
未初始化
  -> 打开通信连接
  -> 探测读写器是否在线
  -> 获取或配置天线
  -> 记录初始化结果
  -> 已初始化
```

初始化失败要求：

- 返回底层错误码和可读错误描述；
- 关闭已经部分打开的句柄；
- 界面禁止开始盘点、读取和写入；
- 日志记录连接参数、设备探测结果和最终错误；
- 对通信超时、设备暂时不可用等可恢复错误执行最多三次初始化尝试；
- 对连接参数非法、驱动缺失等不可恢复错误直接失败，不进行无意义重试。

## 8. 标签盘点和稳定判定

### 8.1 盘点要求

- 持续盘点时间窗口固定为 1000 ms；
- 使用选中的天线和 ISO15693 协议；
- 每轮盘点记录耗时、发现的 UID、天线号、RSSI 和读到次数；
- 盘点期间 UI 不得阻塞；
- 盘点结束后必须停止设备循环并复位通信超时。

### 8.2 稳定判定规则

为了让“稳定读取”可以被测试，V1 固定采用以下规则：

- 在连续盘点结果中，目标 UID 在 1000 ms 窗口内至少被成功发现 2 次；
- UID、协议类型和天线号一致；
- 两次发现之间不能出现明确的设备错误；
- 若窗口内发现多个 UID，业务层返回“标签不唯一”，不自动选择；
- 到达 1000 ms 仍未满足条件，返回超时；
- V1 参数固定为：窗口 1000 ms、目标 UID 最少出现 2 次、允许 UID 数量为 1；参数可定义为代码常量，但不提供 UI 配置入口。

稳定状态输出：

```text
WAITING_FOR_TAG
TAG_DETECTED
TAG_STABLE
TAG_NOT_UNIQUE
TAG_TIMEOUT
```

## 9. 读取流程

```text
检查设备已初始化
  -> 盘点 1 秒并确认唯一稳定标签
  -> 设置访问天线
  -> 按 UID 连接标签
  -> 获取 block 大小和容量
  -> 读取 block 0 开始的协议头
  -> 校验版本和 contentLength
  -> 计算完整 payload 所需 block 数
  -> 读取剩余数据
  -> 解码并校验字段
  -> 输出 HEX + 字段内容
```

读取失败时必须区分：

- 设备或通信失败：允许重试；
- UID 不稳定或标签不唯一：允许重新盘点；
- 版本不支持、长度非法、编码非法：协议错误，不应盲目重试；
- 数据容量不足或越界：协议/设备能力错误，不应重复写入。

## 10. 写入流程

```text
校验用户输入
  -> TagPayloadCodec 编码
  -> 检查标签容量和 block 数
  -> 盘点 1 秒并确认唯一稳定标签
  -> 设置访问天线
  -> 按 UID 连接标签
  -> 按 block 写入，从 basic index 0 开始
  -> 重新读取同一 payload
  -> 对比写入前后的有效 payload
  -> 成功或进入重试
```

写入必须采用“写入后读取校验”，不能仅以底层写接口返回成功作为最终成功。

重试时每次尝试都必须重新确认标签句柄状态；必要时断开并重新连接标签。不得在同一个已经失效的标签句柄上盲目重复调用写接口。

## 11. 重试和异常处理

### 11.1 重试策略

- 单个完整业务操作最多 3 次尝试；
- 尝试计数从 1 开始；
- 每次失败记录错误码、错误阶段和重试次数；
- 第 3 次失败后返回最终失败，不再自动调用设备接口；
- 第 1 次失败后等待 300 ms，第 2 次失败后等待 500 ms，再发起下一次尝试；等待必须使用异步定时方式，不得阻塞 UI 线程；
- 输入校验错误、协议版本不支持、字段长度非法不进入重试；
- 标签离场、通信超时、读写返回错误、读后校验不一致可进入重试。

### 11.2 推荐错误分类

```cpp
enum class RfidErrorKind {
    None,
    InputInvalid,
    ReaderNotReady,
    InventoryTimeout,
    TagNotUnique,
    TagConnectFailed,
    ReadFailed,
    WriteFailed,
    VerifyFailed,
    UnsupportedFormat,
    InvalidPayload,
    CapacityExceeded,
    Cancelled,
};
```

业务结果至少应包含：

```cpp
struct RfidOperationResult {
    bool success;
    RfidErrorKind errorKind;
    int sdkErrorCode;
    int attemptCount;
    QString message;
    QByteArray rawData;
    TagPayload payload;
};
```

## 12. 日志规范

日志必须输出到界面。本地日志文件功能保留，但默认关闭。每条日志包含：

```text
[时间][级别][阶段][尝试次数] 消息 key=value
```

级别：`INFO`、`WARN`、`ERROR`。

必须记录：

- 初始化开始、参数、设备探测结果和结束状态；
- 1 秒盘点窗口内的 UID 变化、出现次数、天线号和耗时；
- 标签连接和断开；
- 写入 payload 的完整 HEX；
- 读取 payload 的完整 HEX；
- 读取后的解析字段；
- 每次失败的 SDK 错误码和阶段；
- 第几次重试以及最终结果。

隐私和安全要求：

- 当前界面必须显示本次读取或写入的完整 HEX、姓名和病历号，方便操作人员核对；
- 本地日志文件默认关闭；启用后，姓名只保留首字符、病历号只保留末 4 位，包含业务 payload 的 HEX 使用 `[SENSITIVE_HEX]` 替代；
- 只有显式启用“敏感数据调试日志”后，本地文件才允许记录完整字段和 HEX；该选项默认关闭，程序重启后自动恢复关闭；
- 不记录通信口密码或未脱敏连接凭据。

## 13. UI 功能要求

界面至少提供：

- 设备初始化/关闭；
- 天线选择；
- 开始盘点/停止盘点；
- 当前稳定 UID、标签类型和 RSSI；
- 皿序号输入；
- 授精时间输入；
- 女方姓名输入；
- 病历号输入；
- 读取业务数据；
- 写入业务数据；
- 原始 HEX 显示；
- 解析字段显示；
- 日志显示；
- 当前阶段、尝试次数和错误信息显示。

按钮状态要求：

- 未初始化：禁止读取、写入和业务盘点；
- 盘点中：禁止重复启动盘点和读写；
- 标签未稳定：禁止业务读写；
- 读写过程中：禁止关闭读写器，或先执行取消并等待线程结束；
- 第三次失败后恢复到可重新发起操作的状态。

## 14. 线程和生命周期要求

- 设备盘点、标签读写和重试流程不得运行在 UI 线程；
- UI 只通过信号/槽或明确的异步结果接收业务结果；
- 关闭窗口时，先停止盘点和业务任务，再断开标签，最后关闭读写器；
- 不允许在线程仍使用 `hr` 或 `ht` 时释放读写器句柄；
- 读写器句柄和标签句柄必须由明确的拥有者管理，关闭时保证只释放一次。

## 15. 验收标准

### 15.1 正常流程

- 设备可正常初始化并显示成功日志；
- 单个标签在 1 秒窗口内稳定出现后，业务读取成功；
- 输入合法数据后，写入从 block 0 开始执行；
- 写入完成后重新读取，解码字段与输入完全一致；
- 女方姓名按 GBK 正确保存和恢复；
- 病历号长度变化时，contentLength 和 block 数量正确变化；
- 日志包含原始 HEX 和解析后的属性内容。

### 15.2 异常流程

- 无标签时 1 秒超时并给出明确提示；
- 同时发现多个 UID 时提示标签不唯一；
- 设备通信失败时最多自动尝试三次；
- 第三次失败后显示最终错误码和错误阶段；
- 空病历号、超过 64 字节的病历号以及包含限定字符集之外字符的病历号被输入校验拦截；
- GBK 编码超过 8 字节时被输入校验拦截；
- 非法版本号、非法长度和截断 payload 被识别为协议错误；
- 写入后校验不一致时视为失败并进入重试策略。

### 15.3 编解码单元测试

至少覆盖：

- 固定示例 payload 的编码结果；
- `2301311743` 编码为 `23 01 31 17 43`；
- 1-4 个汉字的 GBK 编码和前置空格补齐；
- 超过 8 字节姓名拒绝编码；
- 不同病历号长度的 contentLength 计算；
- payload 编码后再解码，字段值保持一致；
- 非法 HEX、非法 ASCII、非法 BCD、截断数据拒绝解码。

## 16. 已确定的协议与产品决策

原始目标中未完全定义的事项，V1 统一按以下规则实施：

1. `内容长度` 表示偏移 2 之后的内容字节数，不包含版本号和长度字段。
2. 姓名 GBK 编码不足 8 字节时，始终在前面填充 `0x20`；读取时只移除这些前导填充字节。
3. 病历号不能为空，只允许 `[A-Za-z0-9_-]`，长度为 1-64 个 ASCII 字节。
4. 标签容量不足时终止当前操作并提示 `CapacityExceeded`，不截断、不覆盖边界外数据，也不自动选择其他标签。
5. 稳定判定使用固定的 1000 ms 窗口；窗口内只允许一个 UID，且该 UID 至少成功出现 2 次。
6. 当前 UI 显示完整业务字段和 HEX；本地文件日志默认关闭，启用普通文件日志时对敏感字段和 payload HEX 脱敏。
7. 可恢复异常最多尝试 3 次；两次重试前分别异步等待 300 ms 和 500 ms。
8. BCD 时间中的两位年份固定映射到 2000-2099。

## 17. 推荐实施顺序

1. 新增 `TagPayload`、`TagPayloadCodec` 和编解码单元测试。
2. 新增 `RfidOperationResult`、错误分类和日志事件模型。
3. 从 `MainWindow` 中抽出业务数据编码和 HEX 处理。
4. 在 `CAEDevice_HF` 外新增 `RfidTagService`，实现稳定盘点。
5. 实现读取流程、动态 block 计算和协议解析。
6. 实现写入流程、写后读取校验和三次重试。
7. 调整 UI，仅保留输入、触发和展示逻辑。
8. 使用真实设备完成正常、无标签、多标签、掉线、写保护和容量不足测试。
