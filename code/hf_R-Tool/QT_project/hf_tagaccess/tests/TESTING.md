# RFID 标签工具整体测试方案

本文用于当前版本的整体验收。先完成不需要设备的自动化测试，再连接读写器和 ISO15693 测试标签进行真机测试。

## 1. 测试前准备

1. 在 Qt Creator 打开 `hf_tagaccess/hf_tagaccess.pro`。
2. 套件必须选择 `Desktop Qt 5.14.2 MSVC2017 32bit`，不要选择名称含 `Python` 的套件。
3. 执行“运行 qmake”，再执行“重新构建项目”。
4. 确认生成目录的 `debug` 文件夹内存在 `Drivers` 目录和 RFID SDK 所需 DLL。
5. 真机写入只使用可擦除的测试标签。业务写入从 block 0 开始，可能覆盖标签原有业务数据。
6. 准备两张 ISO15693 标签：一张用于单标签业务测试，另一张用于多标签和持续盘点测试。

## 2. 当前数据格式

业务数据从 block 0 开始。第二个字节现在表示整条有效数据的总字节数，包含版本号和长度字段本身。

| 偏移 | 字段 | 长度 | 编码 |
| ---: | --- | ---: | --- |
| 0 | 格式版本号 | 1 | Byte，0-255 |
| 1 | 总长度 | 1 | Byte |
| 2 | 皿序号 | 1 | Byte，0-255 |
| 3 | 授精时间 | 5 | BCD，`yyMMddHHmm` |
| 8 | 女方姓名 | 8 | GBK，不足前补空格 |
| 16 | 病历号 | 动态 | ASCII |

示例：病历号为 `2678453101` 时，整条数据长度为 `26`，长度字段应为 `0x1A`。程序也能读取旧规则写出的 `0x18` 数据，不会截断病历号。

## 3. 自动化测试

这些测试不需要连接读写器或放置标签。逐个打开下列 `.pro` 文件，选择上述 Desktop 套件后依次执行“运行 qmake、构建、运行”。每个测试的输出都必须为 `0 failed`。

| 测试工程 | 验证内容 |
| --- | --- |
| `tagpayloadcodec/tst_tagpayloadcodec.pro` | BCD 时间、GBK 姓名、病历号校验、整体长度 `0x1A`、旧长度格式兼容、分块补零 |
| `rfidtagservice/tst_rfidtagservice.pro` | 稳定标签判定、容量检查、空白标签写入、旧数据读取、按长度读取业务块、写后回读校验、写成功但通信失败后的确认 |
| `rfidretrypolicy/tst_rfidretrypolicy.pro` | 可重试错误、最多 3 次、300ms 和 500ms 间隔 |
| `rfidoperationrunner/tst_rfidoperationrunner.pro` | 异步重试、第三次停止、取消等待中的重试 |
| `rfidlogger/tst_rfidlogger.pro` | 日志格式、控制台完整数据、文件默认脱敏 |
| `rfidlogdispatcher/tst_rfidlogdispatcher.pro` | 控制台分发、本地文件写入和脱敏处理 |

本次已在 VS2017 x86 环境实际通过：

- `TagPayloadCodecTest`：8 项通过。
- `RfidTagServiceTest`：15 项通过。
- 主程序 `hf_tagaccess.exe`：重新编译和链接通过。

## 4. 读写器连接与日志

1. 启动主程序，在读写器设置中选择正确的串口、波特率、帧格式和读写器型号。
2. 点击“打开读写器”。
3. 预期：界面提示打开成功，天线列表可用；控制台出现 `INIT` 成功日志。
4. 打开程序生成目录下的 `log` 文件夹。
5. 预期：本次运行产生一个新的 `rfid-日期-时间-进程号.log` 文件。重新启动程序后应生成另一个文件。

断开读写器或填写错误串口后，再点击“打开读写器”。预期日志依次出现第 1 次失败、等待 300ms、第 2 次失败、等待 500ms、第 3 次失败和最终失败；程序不能进入盘点或读写状态。

## 5. 持续盘点与普通块操作

1. 放置一张或多张标签，切换到“持续盘点”。
2. 点击开始盘点，确认列表显示 UID、天线、协议、RSSI 和读取次数。
3. 多张标签同时出现是允许的；停止盘点后，在 Access 页的标签下拉框中选择其中一张并连接。
4. 点击“获取标签状态/系统信息”，确认能获取 block 大小和 block 数。
5. 先用“读块”读取 block 0，记录原始 HEX。
6. 仅在测试标签上用“写块”写入少量已知 HEX，再读回确认一致；最后恢复第 5 步记录的原始内容。

预期：持续盘点结果可用于普通 Access 块读写，但不能直接用于业务数据读写。

## 6. 业务扫描

业务操作只能使用“业务扫描”获得的唯一稳定标签。

### 6.1 单标签稳定扫描

1. 移开所有标签，切换到“业务扫描”。
2. 放入一张 ISO15693 标签，点击开始扫描，并在天线范围内保持约 1 秒。
3. 预期：界面显示标签稳定；列表只有一个 UID；连接标签后“读取业务数据”和“写入业务数据”可用。
4. 查看日志，预期至少出现 `SCAN` 开始、`SCAN_CHANGE`（`previousUids=NONE`、`currentUids=标签 UID`）和 `SCAN` 完成。

### 6.2 UID 变化日志

分别执行两次扫描：

1. 点击扫描后约半秒再放入标签，预期日志出现 `previousUids=NONE`、`currentUids=标签 UID`。
2. 点击扫描后先放入标签，约半秒后移开，预期日志出现 `previousUids=标签 UID`、`currentUids=NONE`，且扫描不满足稳定条件。

### 6.3 无标签和多标签

1. 无标签时开始扫描：预期提示 1000ms 内未发现标签，业务按钮禁用。
2. 同时放入两张标签：预期提示发现多张标签，业务按钮禁用。
3. 两张标签交替靠近天线：预期日志记录 UID 集合变化，扫描不能作为业务读写来源。

## 7. 业务数据读取

1. 先按第 6 节获得一张稳定业务标签，并在 Access 页连接该标签。
2. 保持标签在天线范围内，点击“读取业务数据”。
3. 对于本程序格式的数据，预期弹出表格，显示版本号、皿序号、授精时间、女方姓名和病历号，并显示原始 HEX。
4. 对于版本号不同但字段布局正确的数据，预期仍可读取并显示该版本号。
5. 对于未知旧数据，预期显示原始 HEX 和提示，不自动改写标签。

读取期间移开标签可测试重试：预期最多 3 次，第一次失败后等待 300ms，第二次失败后等待 500ms，第三次失败后结束。日志应包含 `ATTEMPT`、`RETRY` 和 `FAILED`。

## 8. 业务数据写入与回读

只在测试标签上执行本节。

1. 先完成业务扫描并连接唯一标签。
2. 点击“写入业务数据”。
3. 建议输入以下数据：版本号 `1`、皿序号 `1`、授精时间 `2023-01-31 17:43`、女方姓名 `张三`、病历号 `2678453101`。
4. 确认弹窗后保持标签不移动，直到提示写入并校验成功。
5. 再次点击“读取业务数据”，确认表格字段与输入完全一致。
6. 检查原始 HEX：第 0 字节应为 `01`，第 1 字节应为 `1A`。

预期：写入后程序自动回读并比较有效数据；一致才报告成功。若写命令返回通信错误，程序会先回读确认是否已经成功写入；未确认成功时才进入后续重试。

## 9. 输入、容量和安全边界

逐项打开“写入业务数据”窗口验证：

| 输入 | 预期结果 |
| --- | --- |
| 版本号或皿序号小于 0 或大于 255 | 控件不允许输入 |
| 时间早于 2000 年或晚于 2099 年 | 控件不允许选择 |
| 姓名为空 | 拒绝写入 |
| GBK 编码后姓名超过 8 字节 | 拒绝写入 |
| 病历号为空 | 拒绝写入 |
| 病历号含空格、中文或特殊符号 | 拒绝写入 |
| 病历号超过 64 个字符 | 拒绝写入 |
| 标签容量不足 | 提示容量不足，且不发生部分写入 |

## 10. 日志验收

控制台日志会保留业务字段和原始 HEX，方便本地调试。本地 `log` 文件默认脱敏：姓名、病历号和 `payloadHex` 不会以完整明文保存；UID、阶段、尝试次数、错误码、扫描变化和重试延时会保留。

一次正常写入的日志至少应包含：

```text
INIT
SCAN
SCAN_CHANGE
READ 或 WRITE
ATTEMPT
TAG_SESSION
COMPLETE
```

一次失败重试至少应包含：

```text
ATTEMPT 1
RETRY delayMs=300
ATTEMPT 2
RETRY delayMs=500
ATTEMPT 3
FAILED
```

## 11. 结果记录与问题反馈

每项测试记录“通过、失败或不适用”。真机测试失败时，提供以下信息：

1. 测试编号和操作步骤。
2. 读写器型号、连接方式、串口和天线号。
3. 标签 UID、标签数量和标签摆放情况。
4. 界面提示和 Qt Creator Application Output 的完整文本。
5. 对应本次运行生成的日志文件。日志已脱敏；不要额外发送包含患者信息的未脱敏数据。
