# RFID Demo 逐行代码解析（业务路径）

> 阅读方法：本文件的每个 `Lx` 都对应源文件的第 `x` 行；引用的代码保持原貌，紧随其后的列表按代码行逐条解释。空行只承担排版作用，单纯的 `#endif`、大括号和成员声明也在说明中覆盖。与硬件 SDK 直接交互的遗留代码仍依原约定排除；`CAEDevice_HF` 只收录业务桥接和稳定扫描。

## 1. `rfidtagtypes.h`：所有层共享的数据契约

### 模块总览

这里没有业务流程，只有类型定义。它决定 UI、服务、适配器之间交换什么数据，以及失败如何被分类。

```cpp
// L1-L8
#ifndef RFIDTAGTYPES_H
#define RFIDTAGTYPES_H

#include <QByteArray>
#include <QDateTime>
#include <QMetaType>
#include <QString>
```

- L1：开始 include guard，避免同一翻译单元重复包含此头文件。
- L2：定义守卫宏；L1 为假时，L2 到末尾之间的内容才会参与编译。
- L4：引入二进制容器，服务于病历号和读回的原始标签数据。
- L5：引入日期时间类型，避免在业务层把时间表示成易错字符串。
- L6：引入 Qt 元类型支持，供结果对象跨线程信号传递。
- L7：引入 Unicode 字符串类型，服务于姓名、错误信息和 UID。

```cpp
// L10-L17
struct TagPayload
{
    quint8 formatVersion = 1;
    quint8 dishNumber = 0;
    QDateTime inseminationTime;
    QString femaleName;
    QByteArray medicalRecordNumber;

```

- L10：声明值对象，而不是 QObject；它应当轻量、可复制、无生命周期管理。
- L11：开始结构体成员区。
- L12：协议版本默认 `1`，使新建对象默认符合当前写入格式。
- L13：皿序号使用无符号 8 位整数，范围和标签中一个字节完全对应。
- L14：在内存中保留强类型时间，编码时才转换成 BCD。
- L15：姓名先保存为 Unicode；编码器负责 GBK 转换和 8 字节限制。
- L16：病历号是 ASCII 原始字节，故用 `QByteArray` 明确其协议属性和字节长度。
- L17：结束 `TagPayload`。

```cpp
// L19-L34
enum class RfidErrorKind {
    None, InputInvalid, ReaderNotReady, InventoryTimeout,
    TagNotUnique, TagConnectFailed, ReadFailed, WriteFailed,
    VerifyFailed, UnsupportedFormat, InvalidPayload,
    CapacityExceeded, Cancelled,

```

- L19：使用 `enum class`，避免枚举项泄漏为普通全局名称，也禁止与整数隐式混用。
- L20：`None` 表示没有业务错误；`InputInvalid` 表示本地校验失败；`ReaderNotReady` 表示读写器不可用；`InventoryTimeout` 表示窗口内没有可用标签。

- L23：`CapacityExceeded` 表示标签容量不足；`Cancelled` 表示用户中止。后二者均不应进入盲目重试。
- L24：结束枚举定义。

## 2. `tagpayloadcodec.h/.cpp`：逐字节协议实现

### 模块总览

`TagPayloadCodec` 是标签数据协议唯一真相源。它不访问 UI 和硬件，因此每个输入输出都应可离线复现。

```cpp
// tagpayloadcodec.h L6-L29
class TagPayloadCodec
{
public:
    static const quint8 FormatVersion = 0x01;
    static const int HeaderFieldLength = 2;
    static const int HeaderLength = 16;
    static const int NameLength = 8;
    static const int MaxMedicalRecordLength = 64;
    static bool encode(...); static bool decode(...);
    static bool encodeBcdTime(...); static bool decodeBcdTime(...);
    static bool padForBlocks(...); static QString toHex(...);
private:
    static bool encodeName(...); static bool decodeName(...);
    static bool validateMedicalRecord(...); static void setError(...);
};
```

- L6：用无状态工具类承载协议算法；全部接口是 `static`，因此没有对象状态会污染下一次调用。
- L9：版本字节当前固定为 `0x01`；写入端用它建立格式约定。
- L10：版本和长度共占 2 个字节。
- L11：固定头部为 `2(版本/长度)+1(皿号)+5(BCD 时间)+8(姓名)=16` 字节。
- L12：姓名字段是固定 8 个 **GBK 字节**，不是 8 个 Unicode 字符。
- L13：病历号最大 64 个 ASCII 字节，受一字节长度字段和业务规则共同约束。
- L15-L18：公开“完整编码/解码”、时间转换、块补齐、HEX 展示；它们是其他模块可依赖的稳定入口。
- L21-L25：姓名和病历号校验是编码内部细节，私有化可防止上层绕过完整协议校验。

### BCD 辅助函数与错误出口

```cpp
// tagpayloadcodec.cpp L5-L10
namespace {
bool isBcdByte(uchar value)
{
    return (value >> 4) <= 9 && (value & 0x0f) <= 9;
}
}
```

- L5：匿名命名空间使函数仅在本 `.cpp` 可见，避免导出无关符号。
- L6：声明单字节 BCD 验证器。
- L8：右移取高半字节，掩码取低半字节；两者都在 `0..9` 才是有效 BCD。
- L10：结束匿名命名空间。

```cpp
// L12-L17
void TagPayloadCodec::setError(QString *error, const QString &message)
{
    if (error)
        *error = message;
}
```

- L12：集中实现可选错误输出，避免每个校验点重复空指针判断。
- L14：允许调用者传 `nullptr`，此时只接收 `false`，不崩溃。
- L15：存在输出地址时才写入中文/英文诊断信息。

### 病历号校验

```cpp

    setError(error, "Medical record number must contain 1 to 64 ASCII characters.");

for (char ch : record) {
```

- L19：进入病历号验证函数；参数是字节数组而非 UI 字符串。
- L21：同时处理空值和超过最大长度两种长度错误。
- L22：给调用方提供具体规则，而不是只返回一个无信息的 `false`。
- L23：立即失败，保证错误数据不能流入容量计算和设备写入。
- L25：逐字节遍历，正是“ASCII 字节校验”的实现。
- L26-L27：白名单包含大小写字母、数字、下划线、连字符；空格和中文都会被拒绝。
- L28：遇到任意非法字节立即失败，不进行部分修复或静默替换。
- L31：所有字节通过才返回成功。

### 时间编码与解码

```cpp
// L38-L53
if (!encoded || !dateTime.isValid() || dateTime.date().year() < 2000
        || dateTime.date().year() > 2099) return false;
const QString digits = dateTime.toString("yyMMddHHmm");
QByteArray bcd; bcd.reserve(5);
for (int i = 0; i < digits.size(); i += 2)
    bcd.append(char((digits.at(i).digitValue() << 4) | digits.at(i + 1).digitValue()));
*encoded = bcd;
return true;
```

- L38-L40：先同时检查输出地址、日期合法性和两位年份解释范围；这三个条件缺一不可。
- L42：得到 10 个十进制数字，例如 `2301311743`。
- L43：声明输出容器；`reserve(5)` 只优化分配，不改变长度。
- L44：每轮消耗两个字符，所以循环步长为 2。
- L45：第一个数字左移四位成为高半字节，第二个数字成为低半字节，二者按位或后形成一个 BCD 字节。
- L46：将局部结果一次性交给调用者，避免失败中途留下部分输出。
- L47：编码成功。

```cpp
// L55-L79
if (!dateTime || encoded.size() != 5) return false;
QString digits;
for (char ch : encoded) {
    const uchar value = static_cast<uchar>(ch);
    if (!isBcdByte(value)) return false;
    digits += QString::number(value >> 4);
    digits += QString::number(value & 0x0f);
}
const QDate date(2000 + digits.mid(0, 2).toInt(), ...);
const QTime time(...);
if (!date.isValid() || !time.isValid()) return false;
*dateTime = QDateTime(date, time);
```

- L55：解码必须接收恰好 5 字节；多读到的块填充不能传入这里。
- L57：保存展开后的 10 位十进制文本。
- L58：逐字节读取 BCD。
- L59：转换为 `uchar`，防止 `char` 的符号位影响位运算。
- L60：先检查每个半字节是否真的是十进制数。
- L61-L62：按高半字节、低半字节的顺序复原文本。
- L65：年份强制映射到 `2000..2099`，与编码前置条件对称。
- L66：再从剩余数字构造时、分。
- L67：BCD 合法不等于日期存在，例如 2 月 31 日；必须交给 Qt 日期对象验证。
- L69：仅在完整构造成功后写回输出。

### 姓名编码和解码

```cpp
// L81-L104
if (!encoded || name.isEmpty()) return false;
QTextCodec *codec = QTextCodec::codecForName("GBK");
if (!codec) return false;
const QByteArray gbk = codec->fromUnicode(name);
if (gbk.contains('?') && !name.contains('?')) return false;
if (gbk.size() > NameLength) return false;
*encoded = QByteArray(NameLength - gbk.size(), ' ') + gbk;
```

- L81：输出地址和非空姓名是编码的最小前提。
- L85：显式选择 GBK，不依赖操作系统 locale。
- L86：极少数 Qt 构建可能缺少该 codec，因此必须防御空指针。
- L90：由 Unicode 转为字节序列；后续长度全按 `gbk.size()` 判断。
- L91：无法转换时 codec 常以 `?` 代替；此检查阻止未输入问号的姓名被静默损坏。
- L95：超过 8 字节直接拒绝，绝不截断汉字的半个字节序列。
- L99：左侧填充空格，使字段严格为 8 字节；读时必须只删除左侧这些空格。

```cpp
// L106-L132
if (!name || encoded.size() != NameLength) return false;
QTextCodec *codec = QTextCodec::codecForName("GBK");
int firstContentByte = 0;
while (firstContentByte < encoded.size() && encoded.at(firstContentByte) == ' ')
    ++firstContentByte;
if (firstContentByte == encoded.size()) return false;
const QByteArray trimmed = encoded.mid(firstContentByte);
*name = codec->toUnicode(trimmed);
if (name->contains(QChar::ReplacementCharacter)) return false;
```

- L106：解码只接受固定字段长度，避免调用方错误地把变长尾部传入。
- L110：从 0 开始寻找第一个非填充空格字节。
- L111-L112：循环逐个跳过左填充；不会删除姓名末尾的空格。
- L113：全空格意味着空姓名，按协议拒绝。
- L117：截取真实 GBK 内容。
- L118：GBK 转为 UI 可显示的 Unicode。
- L119：替换字符意味着字节序列非法或不可映射，不能悄悄显示错误姓名。

### 完整 payload 的编码、解码与块补齐

```cpp
// L134-L163
if (!encoded) return false;
QByteArray time; QByteArray name;
if (!encodeBcdTime(payload.inseminationTime, &time, error)
        || !encodeName(payload.femaleName, &name, error)
        || !validateMedicalRecord(payload.medicalRecordNumber, error)) return false;

result.append(char(payload.formatVersion)); result.append(char(totalPayloadLength));
result.append(char(payload.dishNumber)); result.append(time); result.append(name);

```

- L134：没有输出缓冲区就不能执行编码。

- L145-L146：长度是 `2 + 1 + 5 + 8 + 病历号字节数`；这里第二字节定义为**总 payload 长度**。
- L148：长度字段只有一个字节，超过 255 必须拒绝。
- L152：预分配最终长度。
- L153：第 0 字节写格式版本。
- L154：第 1 字节写总长度；这是读路径计算块数的依据。
- L155：第 2 字节写皿序号。
- L156：紧接着追加 5 字节 BCD 时间。
- L157：追加固定 8 字节 GBK 姓名。
- L158：追加变长病历号，形成完整协议数据。
- L159：在所有 append 完成后输出；该函数不碰设备。

### 架构沉淀

这一模块的逐行要点是“所有协议边界检查均在设备调用之前完成”。没有它，UI 输入和标签脏数据会直接污染硬件流程。

## 3. `rfidretrypolicy` 与 `rfidoperationrunner`：逐行看重试状态

```cpp
// rfidretrypolicy.cpp L3-L26
switch (errorKind) {
case ReaderNotReady: case InventoryTimeout: case TagNotUnique:
case TagConnectFailed: case ReadFailed: case WriteFailed: case VerifyFailed:
    return true;
case None: case InputInvalid: case UnsupportedFormat: case InvalidPayload:
case CapacityExceeded: case Cancelled:
    return false;
}
return false;
```

- L3：根据错误的**业务语义**而非 SDK 数字码分类。
- L5-L11：这些错误通常有瞬时性，例如标签离场、通信超时、读回校验失败，因此允许再次完整尝试。
- L12-L20：本地输入、协议格式、容量和取消不可能靠重试修复，必须立即结束。
- L22：理论上不可达的防御返回；enum 后续新增值时会默认不重试，行为保守。

```cpp
// L28-L37
return failedAttempt >= 1 && failedAttempt < MaxAttempts && isRetryable(errorKind);
if (failedAttempt == 1) return 300;
if (failedAttempt == 2) return 500;
return 0;
```

- L28：失败次数从 1 开始；上限为 3，所以只允许第 1、2 次失败后重试。
- L31：第一次失败后等待 300 ms。
- L33：第二次失败后等待 500 ms。
- L35：不该重试或已用尽次数时返回 0；Runner 不会据此再次调度。


- L16：尝试数归零，下一次会递增为 1。
- L17：新任务清除旧任务的取消状态。
- L18：允许调用方为某些操作关闭自动重试。
- L19：先设置运行状态，再进入尝试，保证同步完成时状态一致。
- L20：立即开始第一次尝试。

- L27：取消函数不直接打断当前 SDK 调用。
